SciNet 的定位已经比之前明确很多：

> SciNet 要把 scientific workflow 的需求翻译成网络可以执行的意图和 traffic class，再通过 agent、network digital twin 和可编程网络基础设施进行控制。

而且第一次明确写出了 UCR 的交付：

> **UCR 负责 Task 3：Monitoring、Agents、APIs 与 Network Digital Twin 的集成。Month 5 的 M3 是“Multi-Agent communicates with digital twin”。**

## Task 1：先把“科学需求”翻译成“网络需求”

Task 1 不只是收集 workflow，而是建立：

```
Scientific workflow
       ↓
workflow intent
       ↓
network requirements / policies
       ↓
traffic classes
       ↓
Science SLA
```

具体包括：

- 调研 ESnet 的 SENSE；
- 收集 INTERSECT 和 HEP workflows；
- 建立 workflow library；
- 用 knowledge graph 关联：
  - workflow 需求；
  - 网络配置；
  - SLA；
- 把 knowledge graph 翻译成网络 traffic class；
- 扩展到 multi-domain decentralized infrastructure。

这里的 “workflow+network foundation model” 暂时不要理解成一定是大语言模型。slides 没定义其形式；它可能是知识图谱、数据模型和学习模型的组合。

## Slides 给出的 SciNet 架构

第二页的图从上到下大致分为四层。

### 1. Science Workflow Intent Characterization

输入是 benchmarked science workflows，负责提取：

- workflow intent；
- network policies；
- Science SLA。

这是“科学语义进入网络”的入口。

### 2. SciNet Flow Engine

内部包含：

- task queue；
- distributed job queue；
- SciNet databases；
- dynamic branching of tasks；
- configuration management；
- conflict resolution；
- 多种 agent：
  - Network Resource Manager；
  - route optimization；
  - security enforcement。

这层把上面的 intent 变成具体任务和网络操作。

### 3. Agentic workflow 与 Network Digital Twin

Agentic workflow 负责：

- make plan；
- execute tools；
- learn；
- optimize。

Network Digital Twin 负责：

- testing；
- configuration checks；
- 在改真实网络前验证 agent 产生的操作。



### 4. Programmable Network Infrastructure

图中列出的底层 agent/API 包括：

- P4Runtime agent；
- SmartNIC control；
- OLCF job submitter；
- MPQUIC agent；
- JSON/YAML infrastructure/hardware APIs。

底层连接跨站点的：

- databases；
- HPC；
- streaming systems；
- cloud；
- accelerated hardware。

外侧还有 SciNet Monitoring and Evaluation Layer，意味着 monitoring 不只是提供 dashboard，而是 agent 做决策、验证效果和闭环控制的输入。

## UCR 具体处在哪里

按 slides 的任务划分，UCR 不负责 Task 1 的 workflow knowledge graph，也不是 Task 2 的 Flow Engine 主负责人。

UCR 位于这个接口位置：

```
SciNet agents / Flow Engine
            ↕
Monitoring + APIs
            ↕
Network Digital Twin
            ↕
P4 / SmartNIC / MPQUIC / hardware agents
```

Task 3 的原文是：

- “Integration with Monitoring, Agents and APIs”
- “SciNet agents will coordinate activities with hardware agents via monitoring and digital twin layers”
- “Merge with Digital twin, test the NDT tool”
- M3：“Multi-Agent communicates with digital twin”

这说明 UCR 很可能要解决的不是“重新发明一个 optimizer”，而是：

1. agent 怎样读取 NDT 的 topology、telemetry 和状态；
2. agent 怎样通过 API 向 NDT 提交网络动作；
3. 怎样在 NDT 内验证 configuration；
4. 多个 agent 怎样协调并避免冲突；
5. 怎样把验证后的动作连接到底层 hardware agent。

其中 1–5 是根据架构作出的解释；slides 尚未把它们细化成正式子任务。

## Task 4 的 demo

计划展示两类 workflow：

- HEP workflow；
- AI workflow。

展示环境包括：

- network digital twin；
- accelerated hardware。

目标之一是参加 SC26 NRE（Network Research Exhibition）。Slides 提到了可能与 NRP、ESnet、American Science Cloud/IRI 合作。

这说明 Phase 1 的最终展示大概不是单纯画网络吞吐曲线，而是：

```
HEP/AI workflow
     ↓
SciNet agents
     ↓
Network Digital Twin
     ↓
programmable/accelerated network hardware
```

但 PDF 没有说明具体采用哪个 HEP workflow、哪个 AI workflow、哪种 accelerated hardware，也没有给性能指标。
