## 二、同学 S 汇报的初版架构（他自称 "very very crude overview"）

### 起点：用户的一句宽泛 prompt

- 用户（科学家）给出一个很宽泛的目标，例："设计一个粒子探测器工具，在某些特定条件下……"（转写含糊："desk particle be tool, something under some certain conditions"）

### Planning agent → 派生多个 agent

- 会有一个 **planning agent**，它可能 spawn 出多个 agent
- **本次讨论先简化为两个**：**workflow agent** 和 **experiment agent**

### workflow agent 要回答的问题

1. **要跑哪些 workflow** 才能让这个 prompt 真正落地 / 需要做什么实验来验证假设
2. **在哪里调度和运行**这个 workflow
3. 实验**需要哪些仪器（instruments）**，以及**这些仪器在哪里可用**

> **KK 在这里插话强调了项目的根本动机**：
> "我们的目标不是只在一个实验室里跑。DOE 之所以把这个项目给我们，是因为我们在寻求一种**无缝的、跨所有这些国家实验室共享设备来做实验**的方式。这是主要原因。"

### workflow agent 如何产生 workflow：借用 WfBench 的技术

- workflow agent 拿到初始 prompt，用 **WfBench 论文里的技术**，基于一个 **reference prompt / reference workflow** 生成**同一 workflow 的一批变体（variants）**，也可能生成新的 workflow
- 量级：一个 workflow 里可能有**上百个 task**；可以生成**一两百个变体**

> **KK 对 WfBench 的理解（重要，界定了它的能力边界）**：
> WfBench **本身不用任何 agent 来生成 workflow**。它是个 **benchmark**，说的是"对这类实验，我观察到的步骤序列是这样的，涉及的计算量是这样的"。

### 交给 workflow simulator，在 digital twin 上跑

- 此时**还不知道在哪跑、怎么跑**，只知道"这些 workflow 是该跑的"
- workflow agent 把这批 workflow 交给一个叫 **workflow simulator** 的工具，这些 workflow 在 **digital twin** 上运行

## 七、⭐ 为什么 agent 要跑在真实 HPC 上 —— agent 间通信就是网络流量

**这一段是本次会议对我们网络任务最直接、最重要的部分。**

同学质疑：「我只需要保证跑 agent，但**为什么非要在 HPC 机器上跑它们**？」「我看不出有理由在那些机器上消耗这么多资源。」

KK 的回答（要点逐条）：

1. **「Agent 到 agent 的通信也是走网络的。」**
2. **这些 agent 不必都在同一个 HPC 集群上 —— 它们可以在不同的 HPC 集群上。**
3. 它们**都得彼此对话，而且是通过网络对话**。
4. 然后**单个 agent 还要通过网络和某些设备对话**。
5. **「所有这些通信，我们都想建模 —— 用这个 digital twin 来建模。」**

关于是否值得消耗真实机器资源，KK 的补充判断：
> 「如果这事足够容易做、而且系统也可用，那么会**更真实一点**：agent 之间怎么对话、信息怎么在 agent 之间流动、以及**信息怎么在 agent 和它们后端的 LLM 之间往返**。」

### agent 协作与 LLM 的关系

KK 强调的对比：
- 「你有**多个 agent 可能在协作，共同生成给 LLM 的 prompt**，以得到正确的答案」
- 而**不是**「各个 agent 各自去发现要做什么，彼此之间没有任何协作」

同学补充确认：
- agent 确实**共享信息**，靠共享来获得「该给 LLM 提供什么 prompt」的智能
- 它们还会用 **实验/仿真产生的数据**（转写作 "directional data"，疑为 "additional data"，**待核对**）作为**与 LLM 对话时 context 的一部分**
- KK 接话：「是的，因为它们可能最终会用这些来决定**下一次实验该怎么跑**。」

### 同学区分出的两类决策

1. **决定下一个实验配置（experimental configuration）该是什么** —— 这由**每个 agent 各自决定**
2. **决定下一步是什么 / 该调用哪个 agent** —— 这是另一回事

> 所以我的感觉是，不管怎样，**一些有意思的研究会从这里出来。**」

KK 关于「驱动力」的说法：
> 「就像对我们来说 paper deadline 是驱动力一样 —— paper deadline、demo deadline、要给能源部长交报告，这些都是驱动我们干活的力量。**这种驱动力越多，我们真正能做出来的研究就越多。**」

### 例子 1：AI agent 设计噬菌体（bacteriophage）

同学提到几天前看到的一项研究：
- 用 AI agent 开发了某种**噬菌体（bacteriophage）**
- 完全基于**先前的研究信息** —— 读已发表的文章 + 材料知识
- 生成了某种噬菌体的**新变体**，用于抑制病毒感染
- 机制说明：噬菌体头部（"crystal head"）里可以插入自己想要的 RNA 链，这些系统会去感染/改变另一个生物体（本例中是细菌）

KK 的反应：
> 「我不喜欢这些东西，因为谁知道以后会对你的身体发生什么。」

### 例子 2：PNNL 的新材料发现提案（未获资助）

- KK 曾和 **Nel(?)** 以及 **PNNL（Pacific Northwest National Lab，"upstate Washington"）** 的一批人一起写过一份 DOE 提案
- 主题是 **new materials discovery**：「我想要一种比钻石还硬的材料」或「我想要某种能用于某个应用的东西 —— 去找到这种新材料」
- 提案里有**两三位**做新材料发现实验的科学家
- **但我们那份提案主要是看怎么更智能地把 CXL 用于存储**
- **没拿到资助**
- 他们的整个想法是：**自动化「为某个应用寻找新材料」的过程**，用 agent 设计各种各样的实验，看能不能找到突破
- KK：「这会非常非常难，因为你得做**上千次实验**，人类会非常吃力。」
- **和 Harvey Newman 他们做的事是同一类** —— 强子对撞机、Stanford，试着跑非常非常多的不同实验
